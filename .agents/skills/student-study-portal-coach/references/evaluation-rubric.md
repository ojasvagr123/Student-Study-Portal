# Interview and quiz evaluation rubric

Score each substantive answer from 0 to 4.

- 4 - Strong: accurate, repository-grounded, explains the end-to-end flow, trade-offs and limitations; no unsupported claims.
- 3 - Good: correct core answer with minor missing depth or one weak connection to the implementation.
- 2 - Developing: partially correct but generic, misses an important layer, or confuses current implementation with a target design.
- 1 - Weak: fragments of correct terminology but material errors or no coherent flow.
- 0 - Incorrect/no answer: contradicts the implementation or cannot address the question.

## Feedback format

1. `Score: N/4`
2. `Correct:` specific points that were accurate.
3. `Missing or risky:` omitted depth, incorrect claims, security concerns, or evidence gaps.
4. `Stronger answer:` a concise interview-ready version.
5. `Follow-up:` one question that tests the missing depth, unless the session is ending.

## Dimensions for a final mock-interview summary

- Project ownership and communication
- Java/Spring Boot fundamentals
- Security and JWT reasoning
- JPA/PostgreSQL and data modeling
- React and frontend/backend contract
- Deployment and operations
- HLD, scaling and trade-offs
- Future product and AI/RAG design

Report each dimension as `strong`, `developing`, or `revisit`. Recommend exactly three next revision tasks, prioritized by interview impact.
